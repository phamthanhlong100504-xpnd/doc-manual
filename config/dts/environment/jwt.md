# JWT Security Configuration

## Standard Configuration

All microservices within the DTS ecosystem that need to validate JWT tokens MUST use the following shared secret to decode the access token generated by the Identity Service.

### Application YAML Setup

Add this configuration to your `application.yaml` (or application properties):

```yaml
jwt:
  secret: ${JWT_ACCESS_SECRET:uPq3xK8mR5vY2wZ9aB4cD7eF1gH3iJ6kL0nO5pQ8rS2tU4vW6xY9zA1bC3dE7fG9}
```

### Claim Structure

The Access Token emitted by `dts-identity` contains the following important payload structure:
- `sub`: (Subject) The UUID of the user. This should be used to extract the `userId`.
- `roles`: An array of strings representing user roles (e.g., `["ROLE_ADMIN"]`).
- `permissions`: An array of strings representing user permissions (e.g., `["questions:create", "users:read"]`).

**Note on Authorities mapping:** 
When configuring Spring Security, it is standard practice in this project to prefix extracted permissions with `PERM_`. Therefore, to secure an endpoint, use `@PreAuthorize("hasAuthority('PERM_questions:create')")`.
